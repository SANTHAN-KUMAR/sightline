# Annotation guideline for partially visible subjects

**Deliverable F6 / R11.** The rule set is `docs/SOLUTION_DOC.md` §6.3, which is grounded in published
conventions (VisDrone occlusion and truncation bins, COCO `iscrowd`, KITTI occlusion levels, CrowdHuman
visible vs full-body boxes, CityPersons ignore regions, TinyPerson `uncertain`/`ignore`, NOMAD's visibility
budget, POP's tight visible-region boxes). This document does two further things the rule set cannot:

1. it states, rule by rule, **how this project's auto-labeller actually implements it**, so a human reviewer
   and the machine agree rather than diverge;
2. it names, without softening, **which parts are not implemented**, so nobody assumes an attribute exists
   because the guideline mentions it.

Every worked example below is a crop of a **real frame with the box the pipeline actually produced** — not a
hand-drawn illustration of intent. They are in `_artifacts/guideline/`, regenerated by
`uv run python tools/capture/guideline_examples.py <run> [...]`, with `examples.json` recording which frame
and which attributes each came from. If a rule and its picture ever disagree, the picture is the evidence.

---

## 1. Box extent — the visible-extent box

**Rule.** Draw the tightest axis-aligned box around all *visible* pixels of the individual, including a lone
limb or head. Never an amodal full-body box: a limb-only prediction would fail IoU 0.5 against an amodal box
of a mostly buried body, and CrowdHuman itself reports full-body boxes suffer high annotator variance.

**How it is implemented.** `tools/capture/labels.py:labels_from_mask` reads the box **exactly** from the
instance-segmentation mask: the extent of every pixel carrying that actor's palette colour. There is no
estimation step, so the box is tight by construction and cannot drift from the visible pixels. The amodal
box is carried *separately* in `amodal_bbox_px` when a reference pass makes it knowable, and is never used as
the training box.

*Examples:* `extreme_smallest_box_in_the_set.png` (6 px — the floor case), `extreme_largest_box_in_the_set.png`
(125 px), `pose_prone.png`, `pose_supine.png`.

**Disconnected parts.** §6.3 says: if debris or water splits the body and the gap is under one body-width,
box the union; otherwise box the larger part and set `occlusion = 2`. **Not implemented.** The mask gives one
connected extent per actor colour, so a genuinely split subject currently yields a single box over the union
regardless of gap size. Recorded as a known deviation rather than silently accepted.

---

## 2. Minimum visible fraction and size

**Rule.** Label whenever any identifiable body part is visible, whatever the fraction — record the fraction
in `occlusion` instead of dropping the instance. Minimum ≥ 8 px on the longer side at the resolution the
detector sees; 4–8 px gets `uncertain = 1` rather than being skipped.

**How it is implemented.** Every actor present in the mask is labelled, with no fraction threshold — the
pipeline cannot silently drop a hard case, because it never decides what to keep. `size_px` (longer side) and
`visible_px` (pixel count) are recorded on every box.

**`uncertain` is NOT implemented.** Boxes below 8 px are written like any other. `tools/capture/validate.py`
warns on boxes under 12 px and `quality_report.py` measures the fraction below the §5.5 20 px rule, so they
are *visible* in the reports — but no per-box `uncertain` flag exists, and evaluation therefore cannot yet
exclude them from scoring the way TinyPerson does. This is the most consequential gap in this document: it
means a 5 px smudge is currently scored as a miss rather than as unresolvable.

## 3. Attributes per box

| Attribute | Rule (§6.3) | Implemented? |
|---|---|---|
| `occlusion` | 0 fully visible / 1 1–50 % hidden / 2 > 50 % hidden | **Yes**, and *measured*, see below |
| `pose` | standing, sitting, prone, supine, half_submerged, trapped, unknown | **Yes**, plus `waving` and `head_only` (deviation, below) |
| `submersion` | — (project addition) | **Yes**: dry / wet / half / head_only |
| `zone` | — (project addition) | **Yes**: settlement / fan / flooded |
| `visible_fraction` | NOMAD-style visibility budget | **Yes** when a reference pass makes it knowable, else `null` — never fabricated |
| `truncated` | 1 if ≥ 50 % of the visible body is cut at the frame edge | **No** |
| `uncertain` | 1 when unresolvable | **No** (see §2) |
| `context` | open_ground / water / debris / vegetation / structure / vehicle | **No** — `zone` + `submersion` carry part of it |
| `visible_parts` | head / torso / limb multi-select | **No** |
| `group_count` | for `human_group` boxes | **No** — one box per individual always |
| `visibility_modality` | rgb_only / thermal_only / both | **No** — thermal is unresolved (see §6) |
| `source` | `auto:<model,prompt,threshold>` or `manual` | **Implicit**: every box in this dataset is `auto:instance_mask` |

**Occlusion is measured, not asserted, and that distinction cost real defects.** `gen_actors.py` assigns an
*intended* occlusion when it lays the scenario out, and five other generators then scatter geometry over the
same ground — `gen_rubble.py` deliberately leans slabs over the fan survivors to create the partial slice.
Nothing told `actors.json`. On 2026-09-11 four survivors were recorded `occlusion: 0` with rubble proven
above them. Two tools now close that loop:

* `tools/scene/check_occlusion_truth.py` — **height-gated**: an occluder only counts if its top rises above
  the ground the survivor lies on. Without the height test, a slab lying *beside* a prone body counts as
  covering them.
* `tools/capture/measure_occlusion.py` — measures occlusion **per observation** from the actor's visible
  pixel count and the frame's own GSD, against a per-pose reference silhouette drawn from that run's own
  clean observations. A pose with fewer than 8 clean observations gets **no** reference and its boxes keep
  `visible_fraction: null` rather than a fabricated number.

*Examples:* `occlusion_0.png`, `occlusion_1.png`, `occlusion_2.png`.

**Pose vocabulary deviation.** The project uses `waving` and `head_only` in addition to §6.3's list. `waving`
is a distinct upright silhouette with raised arms and is a meaningful triage signal (a person signalling is
conscious). `head_only` is the extreme of `half_submerged` and is separated because §5.3b treats it as its
own coverage layer. Both are supersets of the rule's vocabulary, not contradictions of it, but a consumer
expecting exactly §6.3's seven values must map them.

*Examples:* `pose_standing.png`, `pose_sitting.png`, `pose_waving.png`, `pose_trapped.png`,
`pose_half_submerged.png`, `submersion_head_only.png`, `submersion_half.png`, `submersion_wet.png`,
`submersion_dry.png`.

## 4. Classes and hard negatives

**Rule.** `human`, `animal`, plus hard-negative classes labelled so they enter training as negatives and are
scored separately: `mannequin_or_statue`, `clothing_only`, `debris_limb_like`, `animal_carcass`, `reflection`.

**How it is implemented.** `human` and `animal` are separated by actor name (`Human_###` / `Animal_###`).
**The hard-negative classes do not exist in this dataset.** Nothing in the scene is a mannequin, a
clothing-only decoy or a deliberate limb-like debris shape, so a detector trained on it has never been shown
the distractors §6.3 expects it to reject. Background tiles (5 % of empty tiles, by
`sightline/detect/dataset.py:build_yolo_dataset`) provide generic negatives only. **This is a real limit on
the precision claim** and is the first thing to add if false positives on debris or glint show up in
evaluation.

---

## 5. The `aerially_detectable = false` case

Two survivors are buried under rubble by `gen_props.py` and `gen_rubble.py` per §2.7: aerial search *cannot*
find them, and that is ground truth rather than a shortfall. `tools/capture/validate.py` **fails** if one of
them ever appears in a label, because if a buried survivor is visible in the mask, the burial geometry is not
doing its job and every recall number computed against them would be wrong in the flattering direction.

---

## 6. Thermal — not annotated

§6.3 specifies `visibility_modality` and a copied thermal-only box carrying `uncertain = 1`. **None of this
is implemented, because thermal itself is unresolved**: the Cosys-AirSim `Infrared` pass renders 100 % grey 0
in this project despite every object accepting a segmentation ID. Until that is fixed there is no thermal
frame to annotate, and F9/F9b remain open. See `docs/TRACKER.md`.

---

## 7. QA and sanity checks

§6.3 asks for a 10 % blind second annotation with stated agreement targets. **That does not apply here in its
literal form**: these labels are machine-read from an instance mask, so there is no annotator variance to
measure — two passes would agree exactly, and a 0.95 agreement figure would be meaningless.

The equivalent guarantee is that the mask and the label agree, and that *is* checked:

* **`validate.py` check C** — every labelled box must contain that actor's palette colour in the mask. This
  is the check that matters most, and it was silently skipped for a whole session while the tool still
  printed "all checks passed - dataset is clean" and exited 0. It now exits **2** when any check does not
  run, and the capture writes `segmentation_palette.json` beside the frames so the check works offline for
  ever rather than only while a simulator happens to be up.
* Sanity checks before export, per §6.3: no box below 4 px, none outside the image, no duplicates at
  IoU > 0.9, class histogram per flight — plus a box-size-vs-GSD test that **fails** on any box implying a
  person larger than 3 m on the ground, which is how a collapsed segmentation palette is caught.

## 8. Files

* **Per-frame JSON** beside every frame: `bbox_px` (inclusive integer pixel indices), `visible_px`,
  `size_px`, `pose`, `submersion`, `occlusion`, `zone`, `group`, `aerially_detectable`, and after
  `measure_occlusion.py --write`, `occlusion_intent` and `visible_fraction`.
* **YOLO txt per frame**, written by `labels.to_yolo` from the **visible** box.
* **Tiled YOLO dataset** via `uv run python -m sightline.detect dataset <run> --out <dir>`: 1024 px tiles at
  20 % overlap cut from the 4K frame **without resizing**, because resizing a 4K frame to 1024 turns a 25 px
  prone person into 6 px.
* `segmentation_palette.json` per run: actor id → RGB, so the label-image check is reproducible offline.

**Coordinate convention, stated once because it is off-by-one bait.** `bbox_px` is **inclusive** integer
pixel indices (`width = x2 - x1 + 1`), while `Detection`/`GtBox` use **continuous half-open** xyxy.
`sightline/detect/dataset.py:capture_box_to_xyxy` is the single conversion `(x1, y1, x2 + 1, y2 + 1)`, and
`tests/test_detect.py` checks it reproduces the run's own YOLO line to 1e-6.

---

## 9. Summary of what is NOT implemented

Listed together so it cannot be missed: `truncated`, `uncertain`, `ignore` regions, the five hard-negative
classes, `context`, `visible_parts`, `group_count` / `human_group`, `visibility_modality`, and the
split-subject rule of §1. The two that most affect a reported number are **`uncertain`** (sub-8 px boxes are
scored as misses rather than excluded) and **the hard-negative classes** (the detector has never been shown a
mannequin, a coat or a limb-like branch and cannot be claimed to reject them).
